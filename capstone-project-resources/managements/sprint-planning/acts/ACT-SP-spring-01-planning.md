## 9. Team Agreements and Working Rules

Document the agreements established by the team during
the sprint planning meeting.

**Git and Version Control:**

- Follow the agreed Git branching strategy.
- Create a dedicated branch for each issue when applicable.
- Use descriptive and consistent commit messages.
- Submit Pull Requests for code integration.
- Require code review before merging when applicable.
- Avoid committing secrets, credentials, or environment files.

**GitHub Projects Management:**

- Keep all sprint-related issues updated.
- Assign a responsible team member to each issue.
- Update issue statuses as work progresses.
- Track progress using the agreed GitHub Projects views.
- Communicate blockers as soon as they are identified.

**Communication and Collaboration:**

- Communicate progress and technical blockers regularly.
- Ask for assistance when facing difficulties.
- Document important technical decisions.
- Coordinate changes that affect other team members.
- Inform the Scrum Master about significant impediments.

**Scope Management:**

- Do not introduce additional scope without discussion.
- Discuss new requirements with the Product Owner.
- Evaluate the impact of proposed changes.
- Update the backlog when new requirements are identified.
