# Code Challenge: Expand the Hospital Management System

## Objective

The Hospital Management System has been successfully designed and
normalized to **Third Normal Form (3NF)**. The current database manages
patients, doctors, specialties, appointments, diagnoses, treatments,
statuses, genders, and phone numbers through a well-structured
relational model.

Your next task is to extend the database by analyzing additional
business requirements and designing **two new entities** that integrate
with the existing system while maintaining the principles of database
normalization.

This challenge will allow you to practice database analysis, relational
modeling, and Entity-Relationship Diagram (ERD) design.

---

# Business Scenario

The hospital administration plans to expand the information system with
new features to improve patient care and hospital management.

The current database stores only the basic information required to
manage appointments. However, hospitals usually maintain much more
information than appointments alone.

As a database designer, you have been asked to analyze the current
system and determine what additional information should be stored.

The new entities should improve the system while avoiding duplicated
data and preserving the Third Normal Form (3NF).

---

# Your Challenge

Study the current database carefully.

Analyze the relationships between the existing entities and identify
areas where the database can be expanded.

You must design **two new entities** that fit naturally into the current
Hospital Management System.

---

# Requirements

For each new entity, you must:

- Define the entity name.
- Identify all required attributes.
- Select the primary key.
- Determine the appropriate data types.
- Define any required constraints.
- Identify the foreign keys.
- Determine how the entity relates to the existing database.

---

# Relationship Analysis

For every new entity, determine:

- Which existing table it relates to.
- The relationship cardinality.
- Whether the relationship is:
  - One-to-One (1:1)
  - One-to-Many (1:N)
  - Many-to-Many (N:M)

Be prepared to justify your design decisions.

---

# Update the Entity-Relationship Diagram

Modify the current ERD by including your two new entities.

Your updated diagram must clearly show:

- All entities.
- Attributes.
- Primary keys.
- Foreign keys.
- Relationships.
- Cardinality.

---

# Update the Relational Diagram

After updating the ERD, create the new relational model.

Your diagram should include:

- Table names.
- Columns.
- Primary keys.
- Foreign keys.
- Relationship lines.

---

# Database Design Rules

Your solution must follow these rules:

- Maintain Third Normal Form (3NF).
- Avoid duplicated information.
- Avoid redundant attributes.
- Every table must have a primary key.
- Every relationship must use foreign keys.
- Use meaningful table and column names.
- Follow consistent naming conventions.

---

# Deliverables

Each student must submit:

- Updated Relational Diagram.
- Description of the two new entities.
- List of attributes for each entity.
- Primary keys.
- Foreign keys.
- Relationship cardinalities.
- A short explanation describing how the new entities improve the

# Evaluation Criteria

Your project will be evaluated based on:

- Correct business analysis.
- Appropriate choice of new entities.

- Proper use of primary keys.
- Proper use of foreign keys.
